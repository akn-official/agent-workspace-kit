Moving your agent workspace to a new PC

Scanned on 3 Nov 2026 from Ashraf's main Windows 11 PC. Written for AKN. Every number on this page comes from the scan. Where a source is a best guess, it is marked likely.

The short answer. The workspace lives in two GitHub repos, and you run one PowerShell script on the new PC.

Private: akn-official/agent-config. This is the full backup: 238 skills, 123 plugins from 14 marketplaces, 5 MCP servers, hooks, settings, research papers, memory notes, your own skills, and the lists of tools and apps. Only you use it.

Public: akn-official/agent-workspace-kit. The same setup minus everything personal: no memory, research, client or own skills, and no keys. Anyone can install it with one line (section 9).

The script installs the base tools, gets the repo and puts everything back. Afterwards you only sign in to a few services by hand (section 4).

1. The three commands

On this PC (old), take a fresh snapshot and push it. Do this any time you add skills or plugins:

cd ~/agent-config
node workspace.js snapshot
git add -A && git commit -m "workspace snapshot" && git push

On the new PC, open normal PowerShell (not as admin), download bootstrap.ps1 from the repo on github.com (the repo is private, so a direct link won't work), and run it:

Set-ExecutionPolicy -Scope CurrentUser RemoteSigned
.\bootstrap.ps1

Then open a new terminal, run claude, type /login, and work through the sign-ins in section 4.

3. How the migration kit works

The kit sits in your existing agent-config repo, so there is still only one repo to keep. That repo is private (checked: gh repo view says PRIVATE), and it must stay private. It now holds copies of third-party skills, which are fine to keep for your own use but not to republish.

FileWhat it does
bootstrap.ps1For a fresh PC. Installs Git, Node, GitHub CLI, Python, Bun, uv, ripgrep and ffmpeg with winget. Installs Claude Code with the official script. Signs in to GitHub and clones the repo. Imports all your apps. Then runs the two scripts below. Safe to run again.
install.jsUnchanged from before. Links ashraf-way and linkedin-refiner into every agent, writes the global rule files, adds the ashraf-way hook, and installs ponytail and caveman.
workspace.js snapshotRun on the old PC. Copies skills, research, memory, Claude agents, OpenCode agents and laya into workspace/. Writes manifest.json with the plugins, marketplaces, MCP servers, settings and tool lists. Writes winget.json.
workspace.js restoreRun on the new PC. Installs the npm, pip and uv tools. Copies skills into place and clones the git skills. Runs gstack's setup. Links skills into the other agents. Restores research, memory and settings. Adds the marketplaces, installs the plugins and adds the MCP servers. It never overwrites a folder that already exists. --dry shows what it would do, and --no-tools skips npm, pip and uv.

What is never copied

  • Logins and keys: .credentials.json, auth.json, .env*, *.key/*.pem. MCP keys become placeholders such as ${MCP_21ST_X_API_KEY}.
  • Build and render output: node_modules, .venv, out, dist, .git, and any file over 20 MB. Your 17 GB of promo-video renders in promo-video-generator/out stay on the old PC. Copy them with OneDrive or a drive if you need them.
  • Claude.ai synced skills (skills/synced), which come back when you sign in, and the October app's hooks and MCP, which its own installer writes.
  • Your permissions.allow list (72 entries). Almost all of them are tied to old project paths.

A secret scan of the 2,131 files in the private snapshot found one Google Maps browser key inside a client skill. That skill is never put in the public kit. Nothing else matched (patterns: Anthropic, OpenAI, GitHub, Google, Slack, AWS, private keys). The public kit is scanned again before every push.

4. New PC, step by step

  1. Windows basics. Sign in to Windows and OneDrive with the same account so Desktop\Projects syncs down. Memory notes are keyed to folder paths, so keep the same folder layout. A different Windows user name is fine.
  2. Get the script. On github.com, open akn-official/agent-config, open bootstrap.ps1, choose "Download raw file", and save it to Downloads.
  3. Run it. Open Start, then PowerShell (the normal 64-bit one, not as admin): 
    Set-ExecutionPolicy -Scope CurrentUser RemoteSigned
cd ~\Downloads
.\bootstrap.ps1
    A browser window opens once for the GitHub login. Step 4/6 (the app import) is the slow one, 20 to 40 minutes depending on your connection.
  4. Close the window and open a new terminal so PATH refreshes. Then run claude and /login.
  5. Sign in where a key or account is needed (these can't be copied safely):
    • 21st MCP: set the key, then re-run restore so it adds the server: 
      setx MCP_21ST_X_API_KEY "your-21st-key"
# open a new terminal, then:
node ~/agent-config/workspace.js restore --no-tools
    • Figma MCP: in Claude Code run /mcp, pick figma, sign in.
    • Codex: codex login. Gemini CLI: run gemini and sign in with Google. OpenCode: opencode auth login.
    • GitHub inside agents is already done by gh auth login from the script.
    • Vercel, Supabase and other project CLIs: install per project when needed (npx vercel, npx supabase).
  6. Apps without a winget package: install October, Hermes, DaVinci Resolve and the Codex desktop app from their own websites. October puts its hooks back on its first run.
  7. Check it worked: 
    claude plugin list | find /c "@"        # expect about 123
dir $HOME\.claude\skills | measure       # expect about 238
claude mcp list                          # playwright, figma, laya, rea (+21st after the key)
node ~/agent-config/workspace.js restore --dry   # should show nothing left to do
    Start a Claude Code session: the ASHRAF-WAY, PONYTAIL and caveman banners should appear at the top.
If something fails, the restore prints FAILED: <command> and the last error line, then carries on. Fix that one item (usually a network hiccup or a missing tool) and run node ~/agent-config/workspace.js restore again. It only does what is still missing.

5. Keeping both PCs in sync

Whichever PC gets a new skill or plugin, run the snapshot there and push. On the other PC, pull and restore:

git -C ~/agent-config pull
node ~/agent-config/workspace.js restore --no-tools

Restore only adds what is missing. It never deletes. If you removed a skill on purpose, remove it on the other PC by hand.

6. Installing any skill or plugin by hand

Every skill or plugin you have was installed in one of four ways. The catalog in section 7 says which way applies to each one.

a. Plugin from a marketplace (Claude Code)

claude plugin marketplace add <github-owner/repo>
claude plugin install <plugin>@<marketplace>
# inside a session the same thing is /plugin

A plugin can bring skills, agents, slash commands, hooks and MCP servers together. All 123 of yours came this way.

b. Skill through the skills CLI (works for Claude, Codex, Cursor, OpenCode, Gemini and more)

npx skills add <owner/repo> --list            # see what a repo offers
npx skills add <owner/repo> --skill <name> -g  # install one, globally

This is how find-skills and the HyperFrames video skills arrived (recorded in ~/.agents/.skill-lock.json).

c. Git clone into the skills folder

git clone --depth 1 https://github.com/<owner/repo> ~/.claude/skills/<name>

Used for gstack (then ./setup, which builds its browser tool with Bun and creates the 53 command skills such as /browse, /qa and /ship), humanizer, ai-second-brain, opus-videos and promo-video-generator.

d. Copy a folder

A skill is just a folder with a SKILL.md. Copying the folder into ~/.claude/skills/ installs it. The snapshot uses this route for the 178 skills whose exact version you want to keep. Some upstreams have changed since you installed them: taste-skill now ships one merged skill instead of the 11 you use.

8. Limits and open points

  • Test, 3 Nov 2026: a real restore into an empty user folder on this PC (without the npm/pip/winget steps). It added 14 of 14 marketplaces, installed 121 of 123 plugins, put 246 skills in place including gstack's commands, and added the MCP servers. 21st was correctly skipped until its key is set. A first run on a truly clean machine is still the final proof.
  • Two plugins are gone upstream and can't be reinstalled anywhere: wealth-management (claude-for-financial-services) and claude-coach (claude-code-skills).
  • Windows paths longer than 260 characters break git clones. Keep your Windows user folder short, which is the default. Git's core.longpaths setting also fixes it.
  • gstack's setup needs Git Bash and Bun 1.4.2 or newer (older Bun crashes). Restore runs bun upgrade first. gstack is cloned at today's upstream version, which is newer than your copy from 25 Jun 2026.
  • Plugin versions come from each marketplace's current state, not the versions you have now. Vendored skills are exact copies.
  • Sources marked likely (OmniRoute, Ruflo, Claude SEO extras, taste skills) were matched by name and inner links, not by an install record.
  • The 127.0.0.1:4000 hooks were left out because the app behind them was not identified.

9. Sharing it with a friend

Your friend doesn't need access to your private repo. They use the public kit. On their Windows PC, in normal PowerShell (not as admin):

Set-ExecutionPolicy -Scope CurrentUser RemoteSigned
irm https://raw.githubusercontent.com/akn-official/agent-workspace-kit/main/bootstrap.ps1 | iex

That one line runs the same six steps as in section 4. It skips the personal rules step, and no GitHub login is needed because the kit is public. Afterwards they sign in to Claude Code with their own account and add their own keys (21st, Figma and so on). Nothing of yours is used.

If they want to keep their own copy and update it later, they can fork the kit. A fork of a public repo is public too, so if they want to snapshot their own memory notes into it, they should make a private copy instead ("Use this template" → Private, or import it as a private repo). snapshot refuses to write into a public repo.

When you add new skills or plugins and want your friend to get them:

cd ~/agent-config
node workspace.js snapshot
node workspace.js kit ../agent-workspace-kit
cd ../agent-workspace-kit; git add -A; git commit -m "update kit"; git push

Your friend re-runs the same one-line command. It only adds what is missing.
